# 后端部署构建更新记录

## 一句话摘要

修复 `prod` profile 因缺少 `pr.datasource.driver-class-name` 无法启动的问题，补齐后端容器构建、Compose 环境变量契约、迁移脚本顺序和本地验证记录；前端部署未改动。

## 背景与目标

- 背景：D06 部署材料写于账号表改名与 P0 缓存之前。使用与 Compose 等价的 `prod` 环境变量启动时，Hikari 报 `Cannot load driver class: ${pr.datasource.driver-class-name}`，后端容器无法启动。
- 目标：让后端镜像和 Compose 在不依赖 `application-dev.yml` 的情况下可启动；部署文档与实际配置保持一致。
- 范围：`backend` 配置、`deploy` 文档、运维文档。不修改 `frontend/`、数据库 schema、业务代码和 `pom.xml`。

## 设计说明

| 决策 | 说明 |
|---|---|
| 默认 driver 放在 `application.yml` | Compose 本来就不注入 driver 变量；默认值让 `prod` 与本地 dev 共用同一份基础配置，避免生产启动依赖一个从未存在的环境变量 |
| 不新增 `application-prod.yml` | 现有 `pr.*` 配置已可被环境变量覆盖，新增 profile 文件会产生第二套配置契约 |
| 沿用现有 Compose 变量名 | 已用 Spring Boot 4 的 `SystemEnvironmentPropertyMapper` 探针确认 `PR_AI_DEEPSEEK_API_KEY` 等名称能映射到 `pr.ai.deepseek.api-key` 这类带连字符的属性 |
| 前端部署不接管 | `deploy/nginx/html` 保留占位页，正式前端由前端负责人构建替换；本次不修改 `frontend/` |

## 关键机制

- 配置绑定：`SPRING_PROFILES_ACTIVE=prod` 激活生产 profile；MySQL/Redis/模型/GitHub 配置由 Compose 环境变量注入；driver 使用默认值。
- 容器构建：`backend/Dockerfile` 使用 JDK 17 多阶段构建，运行镜像非 root，产物名与 `pom.xml` 的 `backend-0.0.1-SNAPSHOT.jar` 一致。
- 启动依赖：backend 等待 MySQL、Redis 健康检查通过后启动。
- 密钥隔离：镜像排除 `application-dev.yml`；`.env` 不提交；文档只写占位符。
- 数据卷升级：已有 `mysql-data` 卷按日期顺序执行 `migration-20261022-retry-of-task.sql`、`migration-20261023-rename-sys-user-to-user.sql`，全新安装只执行 `schema.sql`。

## 一致性与权限

- `deploy/README.md`、`docs/部署与安全检查.md`、`deploy/docker-compose.yml` 三处环境变量与启动命令保持一致。
- 未修改数据库 schema 和迁移脚本，不影响现有数据。
- 验证使用临时 Redis DB 15，结束后清空；未创建业务任务，未修改正式前端。

## 风险与后续

- Docker 镜像构建、Compose 实际启动和 Nginx 配置仍需在安装 Docker 的目标机执行一次。
- 生产环境必须替换 `schema.sql` 的 admin/demo 默认密码，或删除种子账号。
- 已有 `mysql-data` 卷升级时必须先备份，并按顺序执行迁移脚本。
- 切换非 MySQL 数据库时，需要通过 `PR_DATASOURCE_DRIVER_CLASS_NAME` 覆盖默认 driver。
- `deploy/nginx/html` 仍是占位页，正式前端页面由前端负责人构建后替换。

## 汇报口径

- 这次修的是部署启动阻塞：`prod` profile 缺少 JDBC driver 配置，后端容器会在 Hikari 初始化阶段直接失败。
- 修复方式是在 `application.yml` 给 driver 一个 MySQL 默认值，不新增 profile 文件，也不改变现有环境变量契约。
- 部署文档补齐了环境变量表、迁移脚本顺序和前端职责边界，前端目录没有改动。
- 本地已用与 Compose 等价的 `prod` 环境变量验证启动、登录、鉴权、OpenAPI 和退出登录，16 个测试通过。
- 开发机没有 Docker，容器构建和 Nginx 校验仍需目标机复验。
