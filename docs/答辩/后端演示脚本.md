# 后端演示脚本

> 目标：现场 3–5 分钟演示完整闭环；任何外部依赖失败都能切到预置任务/fake 兜底。
> 真实 Key、数据库密码不写入本文和 PPT。

## 1. 演示前 10 分钟检查

```powershell
# 1) 启动 MySQL 服务（需管理员）和 Redis
# 2) 后端（示例：fake 兜底）
cd backend
.\mvnw.cmd -q -DskipTests package
java -jar target\backend-0.0.1-SNAPSHOT.jar --server.port=18080 --pr.ai.provider=fake

# 3) 前端联调页（仅演示用，未纳入仓库）
cd frontend
npm run dev
```

- 浏览器打开 `http://127.0.0.1:5173`
- 演示账号：`demo / demo123`；管理员：`admin / admin123`
- 确认 `/api/auth/login` 返回 200，任务列表有已完成/部分完成预置任务
- 真实模型演示时使用 `--pr.ai.provider=deepseek`，并确认 Key 只在本地配置/环境变量

## 2. 演示 PR 清单

| 用途 | PR | 说明 |
| --- | --- | --- |
| 正常/已知缺陷 | `https://github.com/octocat/Hello-World/pull/11596` | README 拼写修改，1 文件、+2 行；适合现场快速跑 |
| 大 Diff/部分完成 | `https://github.com/vercel/next.js/pull/100042` | 187 文件；不建议现场跑真实模型，使用预置任务 |
| 无缺陷/纯文档 | 同 README PR 或预置 task | 检查不误报高危 |
| 跨文件 | 预置受控 fake/单测案例 | 当前缺少稳定真实跨文件 ground truth；现场先展示预置证据，如实说明 |
| 异常 | 非法 URL、预置超时/恢复任务 | 无效 URL、5/6、5/8、4/7 |

## 3. 正常链路（2–3 分钟）

1. **登录**：demo 登录，展示任务列表和用户菜单。
2. **无效 URL**：输入 `not-a-pr-url`，展示 400 明确错误（可选，10 秒）。
3. **预览真实 PR**：粘贴 README PR，点击预览。
   - 预期：`octocat/Hello-World #11596`、作者、分支、head SHA、1 文件、+2/−0。
4. **创建任务**：报告语言选中文，点击开始分析。
   - 预期：跳转任务详情，status 1 排队 → 2 分析中 → 3 完成。
   - 进度来自 `/tasks/{id}/progress`，刷新不丢。
5. **报告**：展示 purpose/changes/impacts、覆盖范围、重点文件。
   - 说明：报告不是“代码正确”的证明，未发现问题≠无缺陷。
6. **文件 Diff**：
   - 打开 README 文件，展示 add 行、结构化行号、问题标记。
   - 打开问题详情，展示证据/建议/置信度；报告级问题没有文件行号。
7. **问题反馈**：把一条问题改为已采纳，填写理由；再撤销，状态回待确认。
8. **导出**：下载 Markdown，展示 PR 信息、提交版本、总结、风险、未覆盖范围。
9. **版本对比**：选择同 PR 的另一个已完成任务，展示 added/remaining/resolved 与总结变化。
   - 如果准备了两个任务：说明行号偏移/低置信匹配提示。

## 4. 游客链路（30 秒，可选）

1. 退出/无痕窗口，首页创建任务（游客）。
2. 展示返回的 `guestToken` 分享链接；无 token 打开任务 → 401/403。
3. 带 token 打开任务/报告/导出；游客不能任务列表、删除、对比。

## 5. 异常与状态（1 分钟，优先用预置任务）

| 展示 | 预期 | 说明 |
| --- | --- | --- |
| 部分完成 | status=4、errorCode=7、hasReport=true | 大 PR/fake 非法输出；保留报告 |
| 模型超时 | status=5、errorCode=6 | 真实 provider + 1ms 读超时已实测 |
| 启动恢复 | status=5、errorCode=8 | 重启时运行中任务标记失败 |
| 取消 | status=6，重复取消幂等 | 已产生结果保留 |
| 删除 | 首次 200、重复 404 | 逻辑删除 |
| 过期 | isExpired 警示 | PR 新提交，旧报告仍可看 |

## 6. 兜底方案

1. 网络/GitHub 不可用：切 fake provider，使用预创建任务，展示完整页面。
2. 模型慢/超时：直接展示预置失败任务和重试入口，不现场重跑。
3. 大 PR 太慢：只展示任务详情/覆盖统计，不点击全量 Diff。
4. 前端异常：用 Swagger/接口结果和 Markdown 报告兜底；说明 API 已通过 40/40 回归。
5. 数据库/Redis：提前启动并保留预置数据；演示前不要清库。
