## 讲法建议

- 中期：把重点放在“问题定义、数据模型、任务状态、GitHub 接入和可运行链路”；AI 只会做演示补充，不抢 UI/原型的重点。
- 结项：先讲完整闭环，再讲三个难点（两阶段 agent、状态机/部分结果、Diff/版本对比），最后用测试指标和部署材料收尾。
- 2026-10-30 增量单独准备 1 页：GitHub OAuth/绑定、用户级 Token、管理员模型配置、用户偏好与停用回退；明确私有 PR 和真实 OAuth App 验收边界。
- 所有“已完成”都对应仓库中的代码/文档；未完成项如实说“前端待补/Docker 待目标机复验”，不要用静态页面冒充真实流程。
