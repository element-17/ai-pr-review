## 幻灯片结构

### 1. 封面

- 项目：AI PR Review 助手平台
- 副标题：面向 GitHub Pull Request 的智能评审 Web 平台
- 本次汇报：后端部分
- 姓名/组号/日期

**讲稿**：
> 我负责后端。今天重点说明需求边界、数据模型、任务状态机、GitHub 接入验证，以及当前可运行的后端链路。

### 2. 项目定位与范围

- 面向开发者：输入公开 GitHub PR，异步分析，输出总结、风险、证据和报告
- 本期做：PR 接入、任务管理、AI 分析、报告/问题/反馈、设置、版本对比、GitHub 登录/绑定、模型配置、部署材料
- 本期不做：私有 PR/私有仓库访问、自动发布 GitHub 行内评论、增量评审（GitHub OAuth 登录已经实现，但 OAuth scope 仍按最小公开 PR 设计）
- 角色：游客、登录用户、管理员

**讲稿**：
> 产品不是“聊天式代码解释”，而是可追溯的 PR 评审工作台。后端负责 GitHub 数据、任务调度、上下文、模型调用、校验入库和权限。

### 3. 业务闭环

```text
输入 PR → 预览元数据 → 创建任务 → 异步拉取文件 → 两阶段 AI 分析
→ 字段/行号校验 → 报告与问题入库 → 用户反馈/导出 → PR 更新后重新分析
```

- 任务与 `head_sha` 绑定，报告、问题、行号同版本
- 游客结果用任务级 token 分享；登录用户历史任务隔离

**讲稿**：
> 这条闭环的关键是“版本一致”和“结果可追溯”。模型输出不直接展示，必须经过后端校验。

### 4. 数据模型

核心 9 表：

| 表 | 关键关系 |
| --- | --- |
| `user` | 账号、角色、状态、password_set |
| `user_github_binding` | GitHub 数字 id 唯一绑定、加密 token、scope/状态 |
| `ai_model_config` | 管理员模型配置、provider、加密 Key、默认/启用 |
| `user_setting` | 用户级主题/语言/分析配置、偏好模型 |
| `pull_request` | PR 元数据和最新 head SHA |
| `analysis_task` | 任务、固定 head SHA、状态机、guest token、model_config_id |
| `task_file` | 文件 patch、变更类型、跳过原因、摘要 |
| `analysis_report` | PR 总结 |
| `review_issue` | 问题、证据、建议、反馈状态 |

- `analysis_task` 一对多 `task_file/review_issue`，一对一 `analysis_report`
- `user_github_binding` 与 `user` 一对一；`ai_model_config` 被 `user_setting.preferred_model_id`、`analysis_task.model_config_id` 可选引用
- 逻辑删除 + 创建/更新时间审计字段
- 复杂筛选走 Mapper XML，单表 CRUD 走 MyBatis-Plus

**讲稿**：
> 这里最重要的一条是 `analysis_task.head_sha` 不可变，报告、文件和问题都挂在任务下；PR 更新只改 `pull_request.head_sha`，用于显示历史报告过期。

### 5. 任务状态机

```text
1 排队 → 2 分析中 → 3 完成
              ├→ 4 部分完成
              ├→ 5 失败
              └→ 6 取消
```

- 阶段：获取 PR → 获取文件 → 补上下文 → AI 分析 → 校验入库 → 结束
- status=4：有跳过/失败文件或模型丢弃，保留结果
- status=2 服务重启 → 5/8
- 取消条件更新；重试 4/5/6 新建任务

**讲稿**：
> 状态全部持久化，刷新不会丢。worker 用 `WHERE status=1` 条件更新 claim，取消也用条件更新，避免并发覆盖。

### 6. GitHub 接入与异步任务

- GitHub REST：PR 元数据、文件清单、patch、commit、文件内容
- GitHub OAuth：登录/绑定、state 一次性校验、一次性 ticket 兑换双 token、AES-GCM 保存用户 token
- Token 选择：已绑定用户 token → 公用 token → 无 token；已绑定 token 失效不回退
- 真实公开 PR 验证：`octocat/Hello-World#11596`、`vercel/next.js#100042`
- 超时/限流：连接 5s、读取 30s；429/5xx 有限退避；错误映射为任务错误码 1–4/10/11
- 异步：固定 worker + 有界队列 + 定时调度；进度轮询；启动恢复

**讲稿**：
> 中期最低目标是真实 PR 可预览、可拉取文件。我们已经跑通真实 PR，并且把 404、限流、超时、无权限都映射成用户可理解的错误。

### 7. 接口与安全约定

- 前缀 `/api`，统一 `{code,message,data}`；成功 200
- 认证：Sa-Token opaque access-token + Redis refresh-token；BCrypt 密码
- 游客：`X-Guest-Token` / `?guestToken=`，任务级有效期
- 数据归属：`TaskAccessService` 统一校验；他人任务 403
- 日志脱敏，不输出 Key/Token/完整代码
- 幂等：创建/重试支持 `Idempotency-Key`

**讲稿**：
> 接口层和 Service 层都不依赖前端隐藏按钮；每个任务子资源都会校验本人或游客 token。
