## 3. 异常状态实测

| 场景 | 操作 | 结果 |
| --- | --- | --- |
| 启动恢复 | SQL 插入 status=2 的任务，重启服务 | status=5、errorCode=8，提示“服务重启导致任务中断” |
| 模型超时 | 真实 provider、`read-timeout-ms=1` 创建任务 | status=5、errorCode=6，提示“模型调用失败” |
| 部分完成 | 大 PR / fake 非法输出 | status=4、errorCode=7，已完成文件和报告保留 |
| 取消 | 排队/运行中取消 | status=6，重复取消幂等 |
| 重试 | 取消任务重试 | 新任务 status=1→2→3，记录 `retry_of_task_id` |
| 删除 | 已结束任务删除 | 逻辑删除；再次删除 404 |

## 4. 状态变更结论

```text
1 排队 --claim--> 2 分析中 --成功--> 3 已完成
                         --跳过/失败/丢弃--> 4 部分完成
                         --致命错误/超时--> 5 失败
1/2 --用户取消--> 6 已取消
2 --服务重启--> 5 失败(errorCode=8)
4/5/6 --重试--> 新任务 1
3/4/5/6 --删除--> is_deleted=1
```

- 状态更新使用条件更新（`WHERE status=...`），避免 worker、取消和重试并发覆盖。
- 部分完成和失败都保留已产生的报告、文件和问题；只有报告生成失败才没有报告。
- 版本对比只接受同一 PR 的 3/4 状态任务，避免比较不同提交版本。
