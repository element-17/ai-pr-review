# 交互流程

> 对应实现基线：`backend-dev` 最新提交（2026-10-30）；当前前端为仓库内 `frontend/` 的 React 实现。2026-10-23 修复与验证见 [前端回归与验收](前端回归与验收.md)；历史临时 Vue 联调页不代表当前前端。
> 数据字段和状态码见 [数据与状态变更.md](./数据与状态变更.md)。

## 1. 角色与页面

| 角色 | 能力 |
| --- | --- |
| 游客 | 预览公开 PR、创建任务、凭 guestToken 查看任务/报告/问题/导出；不能列表、设置、对比、删除、管理 |
| 登录用户 USER | 本人任务、设置、报告、反馈、导出、版本对比 |
| 管理员 ADMIN | 用户管理、用户状态/角色、统计；不是任务所有者时不能读他人任务 |

页面：登录/注册、游客首页/用户首页（同为 `/`，按登录状态展示）、任务列表、任务工作台（总览/文件 Diff/问题/版本对比）、设置。

## 2. 登录与游客

```text
打开 /login
  → 输入用户名/密码
  → POST /api/auth/login
  → 保存 accessToken + refreshToken + userInfo
  → 跳转 redirect 或首页
  → 之后请求带 Authorization: Bearer <accessToken>
```

- access-token 过期（30 分钟）时，前端收到业务码 401，使用 refresh-token 换新 token 并重试一次；旧 refresh-token 立即失效。
- 刷新失败：清空本地 token，跳登录。
- 注册表单按当前 `RegisterDTO` 做前端校验：用户名 3–50 位且仅允许英文字母、数字和下划线；密码 6–32 位且不能全为空白；可选昵称最多 50 字符，可选邮箱最多 100 字符并校验格式，可选手机号须为 `1[3-9][0-9]{9}`。字段失焦后显示错误，修正后清除；提交前重新检查所有字段，不通过则不请求接口并定位首个错误。可选空字段省略，密码不去空格；注册成功返回登录页并保留 returnTo。用户名重复等最终结果由后端校验，界面显示对应错误。当前与历史契约的区别见 [接口文档 3.1](接口文档.md#31-注册)。
- 登录后点击本人头像（桌面侧栏底部，手机顶部）打开个人资料弹窗，每次通过 `GET /api/auth/me` 读取当前账号。展示接口提供的用户名、昵称、邮箱、手机号、角色、状态和时间；缺失字段显示“未提供”，失败可重试。关闭按钮、Esc 或点击遮罩返回原页面，保留筛选条件；会话失效时关闭弹窗并按登录恢复流程处理。
- 游客首页不显示任务列表/设置入口；创建、重试或成功访问后在当前标签页 `sessionStorage` 保存 taskId→token 和已知有效期，并在任务子资源请求头带 `X-Guest-Token`。已知过期凭证不自动复用；页面展示服务端返回的有效期，未提供时说明期限由服务端决定。
- 未登录首页使用独立游客页面，导航及标题为“游客首页”，提供“体验公开 PR 评审”和“打开游客结果”，说明结果链接与有效期，并提供登录/注册入口。游客结果表单要求填写令牌或使用本标签页已保存的有效凭证，缺少时不请求任务接口。登录后回到原用户首页，PR 链接及报告语言查询参数保留；游客任务工作台返回首页的面包屑也显示“游客首页”。
- 游客分享链接：`/tasks/{id}?guestToken=...`；导出用 `?guestToken=`。令牌过期后返回 403。

## 2.1 GitHub 登录与绑定

```text
登录页点击“使用 GitHub 登录”
  → GET /api/auth/github/login/authorize
  → 浏览器跳转 GitHub 授权页
  → GitHub 回调后端 /api/auth/github/callback
  → 后端校验 state、创建/匹配本地用户
  → 302 到前端 /auth/github/callback?ticket=...
  → POST /api/auth/github/exchange {ticket}
  → 保存 LoginVO（与账密登录相同）
```

- 失败时回调到前端 `?githubError=...`；用户取消、state 过期、邮箱冲突、账号已绑定其他账号分别展示对应文案。
- 已登录用户在设置/账号页点击“绑定 GitHub”：
  - `GET /api/auth/github/bind/authorize` → GitHub → 后端回调 → 302 `?githubBind=SUCCESS` 或 `?githubBindError=...`。
  - 绑定状态通过 `GET /api/auth/github/binding` 读取；解绑 `DELETE /api/auth/github/binding`。
  - `passwordSet=false` 的 GitHub 创建用户必须先设置密码，再允许解绑。

## 2.2 模型偏好与管理员配置

```text
设置页（登录）
  → GET /api/models/available（只含 enabled）
  → PATCH /api/users/me/settings {preferredModelId}
  → 返回 preferredModelId / preferredModelEnabled / effectiveModel
```

- 偏好模型被管理员停用后，设置页显示回退提示；任务创建使用 `effectiveModel`。
- 管理员在管理端维护 `/api/admin/model-configs`：新增/编辑/启停/设默认/测试连接；普通用户无权访问。
- 任务详情/报告展示 `modelDisplayName`、`modelProvider` 和 `analysisConfig.model` 快照；历史任务不因模型改名/停用而变化。

## 3. PR 预览 → 建任务 → 异步进度

```text
首页输入 GitHub PR URL
  → POST /api/prs/preview
  → 预览卡：repo #number、title、author、state、分支、head SHA、文件数/增删行
  → 选择报告语言（任务级固定）
  → 点击“开始分析”
  → POST /api/tasks（幂等键）
  → 返回 taskId/status=1/stage=1/progress=0；游客返回 guestToken/shareUrl
  → 跳转 /tasks/{id}
  → 每 2 秒 GET /tasks/{id}/progress
  → 1 排队 → 2 分析中 → 3/4/5/6
  → 进入终态后加载 detail/report，停止轮询
```

- 预览可复用同 head SHA 的已完成任务；展示“查看旧结果”。
- 创建时同用户同 PR 同 head SHA 有运行中任务返回 409；幂等键相同请求返回同一 taskId，不同请求体返回 409。
- 任务详情展示 `isExpired`、`modelName`、`analysisConfig` 快照。
- 页面刷新后重新读取详情和进度，不依赖前端内存。

## 4. 工作台总览

```text
任务详情
  → 状态标签 + stage/progress
  → 报告区：purpose/changes/impacts（null 显示未生成）
  → 覆盖范围：total/analyzed/skipped/failed
  → 统计：文件四项 + 问题状态/严重度
  → 重点文件：filePath/priorityReason/issueCount
  → 操作：取消（1/2）、重试（4/5/6）、删除（本人 3/4/5/6）、导出、分享、对比
```

- status=4 顶部提示“部分完成”，展示跳过/失败原因；status=5 展示 errorCode 原因和重试；status=6 显示已取消但可查看已有结果。
- `isExpired=true` 显示版本过期提示和“重新分析”，旧报告的建议与反馈在前端只读。“重新分析”带入原 PR 与报告语言，仍需预览和确认代码发送提示后建任务；查看、导出和定位旧结果仍可使用。此为界面限制，写入权限和业务规则仍须由真实后端校验。

## 5. 文件 Diff → 问题

```text
文件 Diff tab
  → GET /files?priorityOnly=&status=&changeType=&keyword=&sort=
  → 点击文件
  → GET /files/{fileId}/diff（结构化）或 /files/{fileId}（原始 patch）
  → rows 按 type 渲染 hunk/add/delete/context
  → issueIds 高亮行；点击显示问题摘要
  → 点击问题 → 问题详情抽屉
  → “定位到文件”带 fileId + startLine 回到 Diff
```

- `patchAvailable=false`/二进制/删除文件显示明确占位。
- `addedLines`/`hunkLines` 只用于调试和定位，不在前端重算问题。
- `githubUrl` 指向固定 head SHA 的文件或 PR files 页面。

## 6. 问题处理与撤销

```text
问题列表（筛选 severity/category/feedbackStatus/keyword/sort）
  → 点击问题
  → GET /issues/{issueId}
  → 修改 feedbackStatus=1/2/3/4、remark（误报必填）、suggestion
  → PATCH /issues/{issueId}
  → 列表和统计刷新
  → 撤销：POST /issues/{issueId}/undo
      → feedbackStatus=1，remark=null，suggestion=aiSuggestion
```

- 低置信度（≤60）和 `evidence=null` 必须显示“需人工确认”。
- 报告级问题 fileId/filePath/行号为空，不伪造定位。
- 每任务问题列表的 `stats` 不受筛选影响，用于全局进度。

## 7. 版本对比

```text
任务详情 → 版本对比 tab（仅登录）
  → 读取同 PR 的其他 3/4 任务
  → 选择 base/target
  → GET /tasks/{base}/compare/{target}
  → 展示 base/target 统计、summary changed
  → added / remaining / resolved 三组
  → lineShifted / matchConfidence=low / matching.note 提示不确定性
```

- 同一任务、不同 PR、未完成任务、无报告/问题 → 409。
- 版本选择每页 100 条加载全部历史分页；问题页文件选择每页 200 条加载全部文件分页，失败时保留重试入口。
- 非本人任务 → 403。
- 报告级问题也可参与匹配；路径别名支持重命名前后路径。

## 8. 导出

```text
任务详情 → 导出 Markdown
  → GET /tasks/{id}/export?format=markdown
  → 登录：Authorization；游客：guestToken 查询参数
  → Content-Type=text/markdown；浏览器下载
```

- 导出语言固定为任务 `reportLanguage`，切换界面语言不影响历史报告。
- 无报告/尚未生成返回 404，前端禁用导出。

## 9. 设置、主题与双语

```text
设置页（仅登录）
  → GET /users/me/settings
  → 修改 theme(1/2/3)、language、checkCategories、ignoreDirs、maxFileCount、maxDiffLines
  → PATCH /users/me/settings
  → 应用主题/语言到当前界面
```

- 设置只影响之后创建的任务；已有任务的 `analysisConfig` 快照不改变。
- 主题三态：浅色/深色/跟随系统；语言 zh-CN/en-US；游客也可本地切换但不写服务端。
- 顶栏主题按钮按当前实际显示颜色直接切换浅色/深色，不循环经过跟随系统。设置可开启按设备当地时间自动切换：07:00–19:00 浅色，其余深色；每 30 秒和页面恢复可见/焦点时检查时间。时间策略开关仅保存在当前浏览器，不向现有设置接口添加新字段；手动点击顶栏按钮会关闭时间策略并同步所选主题。
- 设置页按外观与语言、重点检查类别、忽略目录、分析规模、数据发送说明分区。桌面右侧导航固定在可视区域内，点击平滑滚动至对应分类；手机使用顶部横向分类导航。减少动态效果偏好启用时直接定位。分类跳转保留未保存的表单内容。
- 忽略目录校验：非空、不能以 `/` 开头、不能含 `..`、不能是 Windows 盘符。
- 模型 Key 只在服务端配置，设置页不展示。

## 10. 失败、取消、重试与恢复

| 场景 | 用户看到 | 操作 |
| --- | --- | --- |
| 排队/运行中取消 | status=6，已有结果保留 | 可重试 |
| 部分完成 4/7 | 顶部部分完成、覆盖范围、失败/跳过原因 | 可重试或查看报告 |
| 失败 5 | errorCode 1–9 对应原因 | 可重试 |
| PR 版本更新 | isExpired 警示 | 重新分析 |
| 服务重启 | status=5/errorCode=8 | 重试 |
| 报告未生成 | 404 | 禁用导出 |
| 无权限/令牌过期 | 401/403 | 登录或重新获取链接 |

## 11. 管理员

```text
/admin（前端扩展）
  → 用户分页/搜索/统计
  → 创建用户、更新资料/角色/状态、逻辑删除
```

管理员接口仅 `ADMIN` 角色可用；不能删除当前登录用户。

## 12. 交互状态原则

1. 所有业务错误以 HTTP 200 + `{code,message,data}` 返回，前端按 `code` 分支，不按 HTTP 状态码猜测。
2. `null` 字段保留，前端区分“值为空”和“字段缺失”。
3. 列表/详情/报告/问题/对比均有 loading、empty、error 状态；部分完成不是成功，也不是失败。
4. 切换主题/语言不重写历史报告；报告语言是任务属性。
5. 任何写操作按钮 loading + 防重复；创建/重试带幂等键。
