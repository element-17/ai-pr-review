# 数据与状态变更

> 对应实现：`backend-dev` 最新提交（2026-10-30）。表结构以 `deploy/sql/schema.sql` 为准。
> 业务交互见 [交互流程.md](./交互流程.md)，需求方案见 [非平凡需求设计说明.md](./非平凡需求设计说明.md)。

## 1. 核心数据表

| 表 | 作用 | 关键字段/关系 |
| --- | --- | --- |
| `user` | 登录账号 | `username` 唯一、BCrypt `password`、`password_set`、`role`、`status`、逻辑删除 |
| `user_github_binding` | GitHub 账号绑定 | `user_id` 主键、`github_id` 唯一、加密 token、scope、token_status、授权时间 |
| `ai_model_config` | 管理员模型配置 | provider、base_url、model_id、加密 API Key、enabled、is_default |
| `user_setting` | 个人设置 | `user_id` 唯一；theme/language/check_categories/ignore_dirs/上限/preferred_model_id |
| `pull_request` | PR 元数据缓存 | `repo_full_name + pr_number` 唯一；最新 `head_sha` |
| `analysis_task` | 分析任务 | `pr_id`、`user_id`、固定 `head_sha`、status/stage/progress、model_name/model_config_id、guest_token、retry_of_task_id、逻辑删除 |
| `task_file` | 任务文件快照 | `task_id + file_path`；patch、change_type、add/delete、语言、状态、skip_reason、priority_reason、summary |
| `analysis_report` | PR 总结 | `task_id`；purpose/changes/impacts；与任务版本绑定 |
| `review_issue` | 候选问题 | `task_id`、file_id 可空、行号可空、类别/严重度/置信度、证据/建议、反馈状态、逻辑删除 |

`analysis_task.head_sha` 是任务创建时固定的版本；`pull_request.head_sha` 会随 PR 更新，仅用于 `isExpired` 判断。

## 2. 枚举与状态

### 2.1 任务状态

| 值 | 含义 | 结束时间 |
| --- | --- | --- |
| 1 | 排队中 | 否 |
| 2 | 分析中 | 否 |
| 3 | 已完成 | 是 |
| 4 | 部分完成 | 是 |
| 5 | 失败 | 是 |
| 6 | 已取消 | 是 |

### 2.2 阶段

`1 排队 → 2 获取 PR → 3 获取变更 → 4 补上下文 → 5 AI 分析 → 6 校验入库 → 7 结束`

失败可能在阶段 2–6 停止；部分完成/完成统一到阶段 7、进度 100。失败不一定有阶段 7，前端按 status 判断。

### 2.3 错误码

`1` PR 无效/不存在，`2` GitHub 限流，`3` 权限不足，`4` GitHub 失败/超时，`5` Diff 过大，`6` 模型超时，`7` 模型格式/部分输出丢弃，`8` 内部错误，`9` 任务创建后 PR 又产生新提交，`10` 用户 GitHub 授权失效，`11` 服务端公用 GitHub Token 无效。

### 2.4 文件/问题枚举

- 文件状态：1 待分析、2 已分析、3 跳过、4 失败。
- 变更类型：1 新增、2 修改、3 删除、4 重命名、5 复制。
- 问题类别：1 逻辑、2 空值/边界、3 异常、4 安全/敏感、5 API/兼容、6 测试缺失、7 其他。
- 严重度：1 低、2 中、3 高、4 严重。
- 反馈：1 待确认、2 已采纳、3 已解决、4 误报。

### 2.5 GitHub 绑定与模型枚举

- 绑定令牌状态 `user_github_binding.token_status`：1 有效、2 失效需重新授权、3 已撤销。
- 模型格式 `ai_model_config.provider`：`OPENAI_CHAT`、`ANTHROPIC_MESSAGES`。
- 模型开关：`enabled` 0/1；`is_default` 0/1。同一时间最多一个 enabled 默认模型。

## 3. 任务状态机

```text
                    ┌──────────────┐
                    │ 1 排队中      │
                    └──────┬───────┘
          claim 条件更新     │
                    ┌──────▼───────┐
                    │ 2 分析中      │
                    └──┬───┬───┬───┘
             成功/部分/失败/取消 │
        ┌──────────┘   │   └──────────┐
        ▼              ▼              ▼
   3 已完成        4 部分完成      5 失败
        │              │              │
        └──────┬───────┴──────┬───────┘
               ▼              ▼
          6 已取消        （重试）
```

### 3.1 创建

1. 解析并校验 PR URL；拉取 GitHub PR。
2. Upsert `pull_request`，固定最新 `head_sha`。
3. 登录用户检查同 `pr_id + head_sha + status in (1,2)` 的运行中任务。
4. 生成 `analysis_config` 快照、报告语言；游客生成 64 位 hex guest_token 和过期时间。
5. `INSERT analysis_task(status=1, stage=1, progress=0)`；提交后投递线程池。
6. 创建事务只写任务；文件/报告/问题由 worker 后续写入。

### 3.2 调度与执行

- `TaskDispatcher` 扫描 status=1，按 `id ASC LIMIT 20`。
- Claim：`UPDATE ... SET status=2, stage=2, progress=5, start_time=NOW() WHERE id=? AND status=1 AND is_deleted=0`。
- 更新 0 行即跳过，保证多实例/多线程不重复。
- `TaskWorker.updateProgress` 只更新 `status=2`；如果被取消，更新 0 行并抛 `TaskCanceledException`。
- 状态/阶段/进度不是内存态，刷新或重启不丢失。

### 3.3 完成与部分完成

- 全部文件成功、无丢弃：`status=3, stage=7, progress=100, error_code=NULL`。
- 有跳过/失败文件、批次失败或校验丢弃：`status=4, stage=7, progress=100, error_code=5/6/7`；保留已写报告/问题。
- 阶段 1 总结失败、PR/GitHub 致命错误：`status=5`，可能没有报告。
- 取消：`status=6`，只更新 status 1/2；已取消再取消幂等返回。
- 启动恢复：status=2 → status=5、errorCode=8、`errorMessage=服务重启导致任务中断`；status=1 重新投递。

### 3.4 重试

允许 status 4/5/6；新建一条 status=1 任务：
- 复制 `pr_id/head_sha/report_language/analysis_config/model_name`；
- 写 `retry_of_task_id`；
- 游客生成新 token；旧任务和旧 token 保留。
- 旧任务不删除、不改状态。

### 3.5 删除

只允许登录本人、status 3/4/5/6；`analysis_task.is_deleted=1`。列表/详情/报告/问题查询都过滤逻辑删除。游客不能删除；运行中删除返回 409。

### 3.6 GitHub Token 选择链

- 已绑定用户：使用 `user_github_binding` 中解密后的用户 token；token 失效（`token_status != 1` 或 GitHub 返回 401）时直接报错，不回退公用 token。
- 未绑定登录用户 / 游客：使用 `pr.github.token` 公用 token；未配置或为占位符时降级为无 token 请求。
- 公用 token 已配置但 GitHub 返回 401：返回 502 / 任务 `errorCode=11`，不静默降级。
- 未认证请求触发限流：接口 429，任务 `errorCode=2`，提示配置服务端 Token 或稍后重试。
- 预览与异步任务使用同一 `GitHubTokenProvider`；任务表只保存 `user_id`，不保存明文 token。
- 预览缓存只缓存无 token 的公开请求；用户 token/公用 token 请求不进入共享缓存，避免私有 PR 元数据跨用户泄露。

### 3.7 模型解析与任务快照

任务创建/重试时的模型解析优先级：

1. 任务级临时覆盖（本期未开放）；
2. 用户 `user_setting.preferred_model_id`（必须 enabled）；
3. 管理员 `ai_model_config.is_default=1` 且 enabled；
4. `pr.ai.provider=deepseek/fake` 环境兜底。

规则：

- 重试优先沿用原任务的 `model_config_id`；原模型停用时回退当前默认/环境兜底。
- 任务创建时写 `analysis_task.model_name`（模型 ID）、`model_config_id` 和 `analysis_config.model` 快照（configId/displayName/provider/modelId/source）；不保存 base URL/API Key。
- 管理员停用用户偏好模型后，保留 `preferred_model_id`，但设置接口 `preferredModelEnabled=false`，`effectiveModel` 回退默认/环境；历史任务仍显示原快照。
- 模型配置变更会驱逐用户设置缓存；任务详情/报告使用任务快照，不按当前配置重新解释历史任务。
- 任务执行时若原模型已被停用，worker 回退当前默认/环境模型；正常情况下任务创建阶段已固定可用模型。

## 4. 文件与分析结果状态

### 4.1 文件

- Worker 拉取 PR files 后写 `task_file`；按二进制、无 patch、上限、Diff 过大写 `status=3 + skip_reason`。
- 成功分析写 `status=2`、summary/priority_reason；批次失败写 `status=4`。
- 文件行号是 patch 的新文件侧行号，前端 Diff 使用同一版本。

### 4.2 报告

- 阶段 1 成功后写 `analysis_report`（purpose/changes/impacts）。
- 报告与任务 `head_sha` 绑定；PR 新提交只影响 `isExpired`，不改历史报告。
- 阶段 1 失败不写空报告；查询返回“报告尚未生成”。

### 4.3 问题

- 阶段 2 每批提交 `submit_issues`；校验通过后 `INSERT review_issue`。
- 文件级问题必须有之后新增行；纯删除/无新行降级为报告级。
- 证据为空 → confidence ≤60；无法定位 → 丢弃或降级。
- 去重键：`file_id/category/normalized_title`；并发批次入库串行化，避免竞争重复。
- 状态字段是 `feedback_status`，与任务 `status` 是两套枚举。

### 4.4 问题反馈

`PATCH /issues/{id}` 可部分更新：
- feedbackStatus 1–4；误报（4）必须已有或同请求提供 remark。
- suggestion 非空，最长 5000；更新 `feedback_user_id/feedback_time/update_time`。
- 游客可反馈，但 `feedback_user_id=NULL`。
- `undo`：状态回 1、remark 清空、suggestion 回 `ai_suggestion`、更新操作时间。

## 5. 游客与版本

### 5.1 游客

- 游客 token 是任务级 64 位 hex，默认 7 天；`expire_time` 到期后任务子资源 403。
- 访问校验顺序：登录本人 → guestToken 匹配且未过期 → 否则 401/403。
- 游客不能列表、删除、设置、对比、管理员；重试产生新任务和新 token。
- 分享链接和导出使用 `?guestToken=`；XHR 可用 `X-Guest-Token`。

### 5.2 版本一致性

- `analysis_task.head_sha` 创建后不变；`pull_request.head_sha` 可更新。
- 详情返回 `isExpired = task.head_sha != pull_request.head_sha`。
- 可复用任务必须同用户、同 PR、同 head SHA、状态 3/4。
- 版本对比必须同 PR、状态 3/4；路径别名支持重命名前后路径。

## 6. 事务与一致性

| 操作 | 事务/并发 |
| --- | --- |
| 创建任务 | 事务写 PR upsert + task；幂等缓存 Redis TTL 10 分钟 |
| Dispatcher claim | 条件 UPDATE，不依赖锁 |
| Worker 进度/完成 | 条件 UPDATE `WHERE status=2` |
| 文件写入 | 按 task；批次独立，失败隔离 |
| 问题入库 | `@Transactional` + 批次保存锁；去重后 insert |
| 反馈/撤销 | 事务更新反馈字段；权限先校验 |
| 删除 | 逻辑删除；查询统一过滤 |
| 游客 token | Redis/数据库字段绑定；过期判断在读路径 |
| 版本对比 | 只读，不修改任务/报告/问题 |

## 7. 状态回归证据

- 正常任务观测 status 1→2→3。
- 取消：1/2→6，重复取消幂等；重试 4/5/6→新任务 1→2→3。
- 部分完成：status=4、errorCode=7，报告保留。
- 模型超时：status=5、errorCode=6。
- 启动恢复：status=2→5、errorCode=8。
- 删除：已结束任务删除成功，重复删除 404。
