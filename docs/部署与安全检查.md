# 部署与安全检查

## 1. 部署材料

| 文件 | 用途 |
| --- | --- |
| `backend/Dockerfile` | JDK 17 多阶段构建，运行镜像使用非 root 用户 |
| `backend/.dockerignore` | 排除本地配置、日志、构建产物和 Git 元数据 |
| `deploy/docker-compose.yml` | MySQL 8.4 + Redis 7.4 + Backend + Nginx |
| `deploy/.env.example` | 密钥占位符；复制为 `deploy/.env` 后填写 |
| `deploy/nginx/default.conf` | 反向代理 `/api/`，静态文件回退到 SPA index |
| `deploy/nginx/html/index.html` | 前端未构建时的部署占位页 |
| `deploy/sql/schema.sql` | 首次创建 MySQL 卷时自动初始化 |

前端不是本仓库交付物；构建后将 `frontend/dist` 内容复制到 `deploy/nginx/html/`。如果前端独立部署，也可以只使用 Nginx 的 `/api/` 反向代理。

## 2. 启动步骤

```bash
cd deploy
cp .env.example .env
# 编辑 .env：MySQL/Redis 密码、模型 Key、GitHub Token、公开地址
# 可选：cd ../frontend && npm ci && npm run build
#       cp -r ../frontend/dist/* ./nginx/html/
docker compose up -d --build
docker compose ps
docker compose logs -f backend
```

访问 `http://localhost/`；API 在 `http://localhost/api/`。

首次启动时 MySQL 自动执行 `schema.sql`。如果 `mysql-data` 卷已存在，schema 不会重复执行；升级时手动执行 `deploy/sql/migration-*.sql`。

## 3. 安全检查

- [x] `application-dev.yml` 在 `.gitignore` 和 `.dockerignore` 中，不进入仓库或镜像。
- [x] `.env` 不提交；`.env.example` 只有占位符。
- [x] 后端镜像使用非 root 用户，日志目录权限限定为应用用户。
- [x] MySQL/Redis 只在 Compose 内部网络暴露，不映射宿主机端口。
- [x] Nginx 添加 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`；请求透传 `X-Request-Id`。
- [x] 应用日志统一脱敏 Authorization、token、password、api-key；不记录完整 prompt/代码。
- [x] 健康检查覆盖 MySQL、Redis；后端启动依赖两者健康。
- [ ] 生产必须修改 `schema.sql` 的 admin/demo 默认密码，或删除种子账号。
- [ ] 生产必须变更 `.env` 中示例密码，并把模型 Key/GitHub Token 放在密钥管理系统。
- [ ] 生产必须由外部负载均衡或 Nginx 终止 TLS；当前配置只监听 HTTP。
- [ ] 备份 `mysql-data` 和 `backend-logs` 卷，定义保留周期。
