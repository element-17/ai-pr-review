### 2.2 开发规范

#### 2.2.1 过程与协作规范

| 规范项 | 要求 |
| --- | --- |
| 迭代管理 | 使用云效进行需求拆解、任务分配和进度跟踪；整个项目至少完成两次迭代；需求、开发任务、缺陷均明确负责人、所属迭代和完成状态，并及时更新 |
| 进度展示 | 答辩时能够展示迭代计划、任务完成情况与当前开发进度 |
| 版本管理 | 使用 Git 管理代码；完成相对独立的功能、修复或调整后及时提交；提交信息需说明变更内容 |
| 提交纪律 | 不得在项目结束时将全部代码作为单次提交上传 |
| AI 辅助开发 | 允许使用 Codex、Cursor 等工具；成员必须理解并能解释所提交代码及关键设计决策；AI 生成内容须经过检查、运行和必要修改，不得以工具结果代替测试与答辩说明 |
| 需求追踪 | 需求、任务、缺陷与功能编号（F/B/D/A）建立对应关系，避免开发范围失控 |

#### 2.2.2 前端开发规范

| 规范项 | 要求 |
| --- | --- |
| 技术框架 | 使用 Vue 3 或 React，二选一并在项目内保持统一；不得仅用静态页面完成项目 |
| 组件库 | 允许使用成熟 UI 组件库：Vue 3 推荐 Element Plus 或 Ant Design Vue，React 可使用 Ant Design；同类组件风格统一 |
| 接口协作 | 尽早与后端确认接口地址、请求参数、返回结构和异常状态；接口调用集中封装，避免在页面组件中重复编写请求与错误处理 |
| 页面状态 | 核心页面完整处理加载中、无数据、请求失败、操作成功等状态；耗时操作展示进度或明确等待提示，防止重复提交 |
| 响应式设计 | 适配 PC 端和移动端；导航、表单、列表和核心操作区域在不同宽度下布局合理、内容可读、操作可用；表格、代码等宽内容提供移动端浏览方式 |
| 代码质量 | 合理划分页面、组件与公共逻辑；命名清晰、类型定义必要；提交前确认项目可正常构建，不遗留明显报错、无效代码或调试内容 |
| 主题与双语 | 主题切换、双语言在页面开发时同步考虑，并检查正常、空数据和错误状态下的显示效果 |

#### 2.2.3 后端开发规范

| 规范项 | 要求 |
| --- | --- |
| 技术栈 | 必须基于 Java + Spring Boot + MyBatis-Plus 实现 |
| 接口风格 | 统一使用 RESTful 风格，接口路径、请求方式、响应格式保持一致 |
| 分层架构 | Controller、Service、Mapper、Entity/DTO/VO 分离；Controller 不写业务逻辑，不直接拼接 SQL |
| 统一响应 | 所有接口统一返回 `code`、`message`、`data`；区分成功、失败、参数错误、权限不足等场景 |
| 幂等处理 | 关键业务接口支持幂等，避免重复提交造成数据异常 |
| 接口文档 | 输出接口文档，便于前后端联调与答辩展示 |
| 建表脚本 | 数据库表结构需提交建表脚本，并说明字段含义、索引设计、外键关系、逻辑删除策略 |

#### 2.2.4 数据与安全规范（中期设计阶段先落方案）

| 规范项 | 要求 |
| --- | --- |
| 数据库设计 | 概念设计与逻辑设计先行；字段、索引、外键、逻辑删除和审计字段在编码前确定 |
| 输入校验 | 请求参数校验必填、格式、长度、取值范围和特殊字符，防止 SQL 注入、XSS、参数篡改 |
| 认证授权 | 统一登录认证机制，禁止接口无鉴权访问；采用 Sa-Token 等方式进行访问控制 |
| 敏感配置 | 访问密钥、数据库密码、模型密钥不得提交至代码仓库；提供配置示例文件 |
| 异常反馈 | 对无效输入、接口失败等常见异常给出明确反馈；不向客户端返回堆栈、SQL 或数据库错误信息 |

> 上述安全细项在中期完成设计与规范约定，结项逐项实现并验收。

#### 2.3.3 业务规则

| 编号 | 规则 | 说明 |
| --- | --- | --- |
| B01 | 评审版本 | 任务由仓库、PR 编号和 head commit SHA 确定；同一报告的总结、问题和行号必须来自同一版本 |
| B02 | 风险分级 | 严重度描述潜在影响，置信度描述证据充分程度，两者分开展示；高严重度低置信度需提醒人工优先核查 |
| B03 | 有效定位 | Review 建议必须关联可查看的文件与行号；无法定位到变更行的跨文件推断只能作为报告级提示 |
| B04 | 部分结果 | 部分完成或跳过文件时，报告必须附分析范围与原因，任务不得直接显示为完整成功 |

### 2.4 技术栈要求

| 类别 | 必须 | 推荐/可选 | 中期落地要求 |

| D01 | 平台实现 | 交付可运行的 Web 前端、Java Spring Boot 后端与 AI 分析模块；前端负责 PR 提交、进度、Diff 与反馈；后端负责 GitHub 数据获取、任务调度、上下文组织、模型调用、结果持久化与权限校验，并说明模块边界 |
| D02 | 模型选择 | 至少比较两种可用模型或两种配置的代码理解效果、结构化输出稳定性、响应时间与调用成本，说明最终选择；不要求训练模型；模型输出经字段和行号校验后入库 |
| D03 | 上下文控制 | 制定上下文获取范围与截断策略，优先读取变更函数、依赖定义和相关测试；说明大 PR 的分块、并发或增量处理方式；后端通过 GitHub API 或受控临时检出获取代码，不得假设浏览器能读取本地仓库；PR 文本与仓库代码按不可信输入处理 |
| D04 | 性能与可用性 | 分析任务异步执行且可取消；页面通过轮询或服务端推送展示进度；刷新后可重新进入任务；GitHub 请求和模型调用设置超时、限流处理与重试边界，记录耗时与失败阶段 |
| D05 | 质量验证 | 建立至少 20 个有明确预期的测试 PR 或变更案例，覆盖普通修改、跨文件依赖、已知缺陷、无缺陷、大 Diff 与异常场景；记录问题有效率、已知缺陷检出率、定位准确率和耗时，分析典型误报与漏报 |
| D06 | 安全与交付 | 不在代码库提交密钥；日志不包含访问令牌或完整私有代码；提供前后端启动与部署说明、数据库初始化脚本、配置示例、接口文档、演示用 PR、测试结果和系统设计说明 |
| D07 | 前端实现 | 至少包含首页、任务列表、PR 总览、文件 Diff、问题详情与处理、版本对比、设置七类界面；采用可复用组件与界面状态、统一主题变量和中英文资源文件；提供界面原型和主要交互流程说明 |

#### 3.3.4 验收标准

| 编号 | 验收项 | 验收内容 |
| --- | --- | --- |
| A01 | 端到端演示 | 在浏览器中使用真实公开 GitHub PR，完成「输入链接—获取变更—生成总结与风险—定位 Diff—人工处理—导出报告」完整流程 |
| A02 | 分析可信度 | 至少演示一个跨文件问题；每条风险可追溯到正确的文件与版本，具有触发条件和证据；误报可由评审者反馈 |
| A03 | 异常与更新 | 演示无效链接、接口失败或模型超时的提示与恢复方式，以及 PR 新提交后旧报告过期的处理 |
| A04 | 评估材料 | 提交测试案例及汇总指标，解释模型选择、上下文获取、误报漏报控制与响应速度之间的取舍 |
| A05 | 界面验收 | 现场演示从总览筛选问题、在 Diff 中定位证据、编辑并反馈建议、查看新旧版本差异，以及加载失败和部分结果状态；桌面和常见平板宽度下可读可操作 |
| A06 | 主题与语言验收 | 依次切换浅色、深色、跟随系统主题并更改操作系统主题，检查各页面同步变化；切换中英文后检查正常、空结果及错误状态；刷新验证偏好保留；确认旧报告不会因界面语言切换被改写 |

#### 3.3.5 加分项（可选）

| 编号 | 功能 | 演示要求 |
| --- | --- | --- |
| X01 | 增量评审 | PR 新增提交后仅重新分析受影响文件或代码块；演示同一 PR 两个版本的差异，并对比完整重跑的耗时与模型用量 |
| X02 | 仓库级上下文检索 | 在函数级上下文之外，通过符号索引或检索查找调用链、接口定义、配置和测试；演示至少一个多文件关联案例并显示证据来源 |
| X03 | 人工确认后发布评论 | 开发者编辑、确认后将建议发布为 GitHub PR 行内评论；处理行号映射、重复发布和 PR 更新后的失效位置；演示发布前预览与发布结果 |
| X04 | 私有仓库支持 | 通过 GitHub 授权访问私有 PR，限制授权范围，安全保存和撤销凭证，清理日志敏感信息；演示授权、分析与撤销后的访问变化 |
| X05 | 测试辅助 | 根据风险问题生成针对触发条件和边界情况的测试思路，可提供可复制或下载的测试代码草稿；演示测试如何复现或排除候选问题 |
| X06 | 反馈驱动质量改进 | 汇总采纳、误报和漏报反馈，按类别统计效果，并用相同测试集比较优化前后的有效率、检出率和耗时 |
| X07 | 自动触发与通知 | 通过 GitHub App 或 Webhook 在 PR 创建、更新时触发分析并提示新报告；校验事件来源、避免同一提交重复执行，演示完整自动触发流程 |
| X08 | 多语言与可配置规则 | 增加另一门语言的符号级分析，或支持可共享的团队规则；演示规则启用前后的结果差异并说明适用范围与误报风险 |

> 加分项不替代基础要求；应优先保证核心流程完整、真实可用。

### 3.4 技术栈要求

| 类别 | 必须 | 推荐/可选 | 结项验收要点 |
| --- | --- | --- | --- |
| 前端框架 | Vue 3 或 React（项目内统一） | TypeScript | 七类界面可运行，构建通过 |
| UI 与样式 | 成熟 UI 组件库 + 统一主题变量 | Element Plus、Ant Design Vue、Ant Design | 浅色/深色/跟随系统同步生效，代码高亮与告警颜色可辨 |
| 国际化 | 中英文资源文件与即时切换 | vue-i18n、react-i18next | 导航、按钮、状态、错误、空结果、日期数字均本地化，偏好持久化 |
| 请求层 | 集中封装的 HTTP 客户端与错误处理 | Axios | 页面不重复编写请求逻辑，异常状态可展示 |
| 后端 | Java 17+、Spring Boot、Maven、RESTful | Spring Boot 4.x | 分层清晰，接口统一返回，异常处理完整 |
| 持久层 | MyBatis-Plus | 条件构造器、分页、自动填充、逻辑删除 | 复杂查询可维护，审计字段与逻辑删除生效 |
| 数据库 | MySQL 8.x | Redis | 提供初始化脚本、索引与关系说明 |
| 认证授权 | 统一认证 + 细粒度权限 | Sa-Token | 敏感接口鉴权，防横向越权，密码加密，登录失败限制 |
| GitHub 接入 | GitHub REST API | GitHub OAuth | 真实 PR 拉取、限流与超时处理、错误可恢复 |
| AI 分析 | 至少一种模型服务，输出结构化校验 | 至少比较两种模型/配置 | 说明选型依据；字段与行号校验后入库 |
| 异步任务 | 异步执行、可取消、状态持久化 | 线程池、消息队列 | 轮询或 SSE 展示进度，刷新后可恢复 |
| 外部调用治理 | 超时、限流、重试边界、耗时与失败阶段记录 | 熔断/降级 | GitHub 与模型调用失败可定位、可重试 |
| 结果与权限 | 报告、问题、反馈持久化；数据归属校验 | — | 用户只能访问自己的任务；游客结果按有效期访问 |
| 测试与评估 | 至少 20 个测试案例与指标统计 | 自动化测试脚本 | 有效率、检出率、定位准确率、耗时、误报漏报分析可复现 |
| 部署 | 前端构建产物 + 后端服务 + MySQL | Nginx、Docker、Redis | 按运行说明可从零启动，配置示例不含真实密钥 |

**现有工程对齐说明**：

- 后端已使用 Spring Boot 4.0.8、Java 17、MyBatis-Plus 3.5.17、MySQL、Redis、Lombok 与 Maven Wrapper，可直接在此基础上实现。
- 正式前端采用 React 19 + TypeScript + Vite，已有七类页面、统一样式组件、主题/双语和响应式布局；`frontend/` 已纳入源码管理。真实后端联调和现场验收须按 [前端回归与验收](前端回归与验收.md) 完成。
- 部署目录已提供 Dockerfile、Compose、Nginx 和检查清单；当前开发机无 Docker，目标机需复验构建和 `nginx -t`。
- 所有真实密钥、数据库密码、模型 Token 只能放在本地配置或环境变量中，仓库仅保留配置示例。
